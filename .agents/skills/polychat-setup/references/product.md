# Understand Polychat

Polychat has two primary modes:

- **Chat** is for personal conversations, models, connected tools, memories and recipes.
- **Work** organises collaboration into workspaces and projects with shared instructions, conversations, sources, outputs, tasks and activity.

## Choose a surface

- Use a **Conversation** for an interactive request.
- Use **Experiences** for structured workflows.
- Use **Sources** for material and media: uploads, transcripts, generated images and video, and podcast episodes with private RSS feeds.
- Use **Project tasks** for work that needs durable status, delegation or delivery.
- Use **Recipes** for reusable, scheduled conversations.

## Scope and controls

Project membership controls shared resources; it does not transfer another member's external credentials. Workspace provider connections belong to the workspace. Personal controls such as pin, unread and snooze remain personal, including in project conversations.

Approvals are stored separately from assistant messages. A project delivery setting expresses intent, while current permissions and any required runner approval govern the actual write.

Model readiness is checked when a run starts. Changing the selected model applies to later runs; compatible history and attachments remain with the conversation.

Usage is reserved before provider work and settled after terminal accounting. See [usage and cost operations](operations/loop-cost-controls.md) for limits and reporting.
