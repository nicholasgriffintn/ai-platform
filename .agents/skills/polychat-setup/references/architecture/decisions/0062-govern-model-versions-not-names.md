# ADR 0062: Govern model versions, not model names

Status: Implemented in `modules/model-registry`, `library-model-registry`, `library-policy`, `ai-model-sources` and `ai-model-providers`.

## Problem

Open models reach production through several hands, each working from a different record. A Hugging Face repository name is a moving target: the same `owner/name` can serve different weights, code and chat templates from one day to the next. Where a model runs carries its own risks, model files can execute code, and a fine-tune combines inputs that neither approval covers. Governance breaks down when a verdict cannot be reproduced, and a platform-owned provider account would centralise every workspace's data, access and bills.

## Decision

- **Versions are the governed unit.** A version is a model or dataset pinned to a Hub commit, with every file's size and LFS SHA-256 recorded at import. Import resolves any branch or tag to its commit first. A version is never edited; a new upstream commit is a new version.
- **Routes are approved separately.** A route is a version served by a provider under a catalogue model ID in a region, with `weightsVerified` true only for dedicated deployments. Route conditions apply only when a route is in play, and a route is usable in a scope when approvals cover both its version and route issues. Under `enforced`, project chats use only approved routes, and a tier-selected model falls back to the first approved route. Generations on an approved route carry `polychat.route_id` and `polychat.asset_version_id`, so usage joins back to a version without new metering.
- **Evidence is append-only and policy is pure.** Checks write dated evidence rows and never update them. Policies are versioned by content hash with every revision kept, and one pure evaluation runs for enforcement, previews, dry runs and replays. Effects combine by severity (`allow < warn < review < block`), and a project policy can only narrow its workspace policy. An approval covers what its approver saw, bound to scope, policy hash and rule ID, so new review issues or a changed policy reopen it. A block is covered only by an exception with an expiry.
- **Untrusted weights are read, never loaded.** Inspection fetches byte ranges from the pinned commit and parses safetensors headers, GGUF metadata, torch zip directories and pickle opcode streams against a known-safe import set. It never deserialises or executes anything, so no container scanner is used. Hub scanner results are recorded alongside, and chat templates that reach for Python internals fail. The scanner reports "no known issues", never "safe"; oversized or unscanned pickles are marked as such.
- **Derived models re-enter the gate.** A fine-tune requires both its base and its dataset to be usable in scope, trains from the pinned base commit and registers as a draft derived version with `fine_tuned_from` and `trained_on` lineage and an estimated `6 × parameters × tokens` compute figure. The output commit is pinned and inspected like any import.
- **Workspaces bring their own accounts.** Providers for registry, training and serving are connected per workspace, sealed at rest and resolved per operation behind shared `ai-model-providers` adapters. The API owns orchestration and policy; there is no separate training worker. Deployments sit behind aliases, promotion is gated on evaluation and approval, budgets are checked before starts, and revocation follows lineage.

## Consequences

An auditor can answer "which weights, approved by whom, on what evidence" from one record, and the ML-BOM export is a projection of it. Imports cost a Hub metadata call and tree listing. A repository that rewrites history can leave versions pointing at missing commits, because Polychat does not take custody of weights. The rule language stays small: a condition that needs a new fact needs a new evidence kind. Workspaces manage their own provider setup and bills, and budget reconciliation runs on a schedule rather than immediately. See [model platform operations](../../operations/model-governance.md).
