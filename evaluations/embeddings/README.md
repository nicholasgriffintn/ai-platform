# Evaluate embedding providers

We lack measured Polychat retrieval results that justify changing the embedding model. **Retain Workers AI BGE Large v1.5** for issue #2178; shortlist Voyage 4 for the next measured text/code comparison. Keep the current `Embedder` capability, storage adapters and `v1` provenance. Do not add a candidate runtime adapter or increment the vector-space version until we select a replacement.

## Run a repeatable comparison

Use `polychat-retrieval-v1.json`: 24 synthetic passages and 18 manually labelled queries covering procedures, code, permissions, negation, dated changes, extracted document text and multilingual search. Grades are 3 (direct answer), 2 (equivalent supporting answer) and 1 (useful context); omitted passages are irrelevant. Treat this as a representative smoke corpus, not a statistical benchmark or evidence of raw multimodal or long-context quality.

```sh
pnpm build:packages
node scripts/evaluate-embeddings.mjs --baseline /tmp/bge-capture.json > /tmp/bge-report.json
node scripts/evaluate-embeddings.mjs /tmp/bge-capture.json /tmp/candidate-capture.json > /tmp/comparison.json
```

Supply `CLOUDFLARE_ACCOUNT_ID` and a Workers AI inference token through the environment for `--baseline`. The command sends only the synthetic corpus to Workers AI, makes sequential single-text requests and measures each query five times. It neither writes vector stores nor starts a server. A failed request, timeout or rate limit aborts the capture; rerun after resolving the quota rather than scoring partial results. Keep captures outside the repository; baseline output refuses to overwrite an existing file.

Capture candidate results with the provider's existing API tooling in the format defined by `embeddingEvaluationCaptureSchema` in `packages/schemas/src/embedding-evaluation.ts`. Embed the identical passage/query strings, preserve their IDs and dataset digest, record one vector per passage, and record five `{ values, durationMs }` samples per query. Set exact provider/model/dimensions/task mode/version, capture time, transport and cache condition; keep `costUsd: null` unless billed usage is known. Use explicit retrieval task inputs for asymmetric models. Each capture is scored independently, so vectors from different models never share a similarity calculation.

Compare Recall@3, MRR@3 and graded nDCG@3 overall and by category, query p50/p95, document embedding time and total billed cost. Review per-query rankings before accepting a gain. Use the same machine, region, repetitions and transport/cache conditions; direct REST measurements do not measure the production Workers binding and three-day gateway cache. Recheck failures and quotas separately, and include full-corpus re-embedding cost in the decision. No live capture was run for this change because provider credentials were unavailable; mocked regression results are not quality evidence.

Select a replacement only after it improves the target workload without unacceptable category regressions, latency, cost or credential/data-handling overhead. Expand the corpus with reviewed, authorised examples and a held-out set before a production decision. Evaluate multimodal inputs separately through an appropriate contract before claiming a multimodal benefit.

## Re-index and roll back

**No migration is required for this retain-BGE decision.** Keep Vectorize and S3 Vectors configured as today, with the existing BGE model, 1,024 dimensions, symmetric task mode and `v1`. Existing runtime-target checks reject unsupported model/dimension/metric/task/version combinations; retrieval generates a query per stored compatible target and checks returned rows against that provenance. Existing `workers-ai` and `baai` icon registrations cover the retained provider/model.

For an explicit BGE re-index, export the original source content, title, type, metadata and logical ID before deleting anything. Use the authenticated embedding delete operation for that ID, wait for successful cleanup, then insert the original source with the same logical ID under the intended configured storage target. The current lifecycle rejects an active duplicate ID; delete/insert causes a search availability gap and allocates new physical chunk/vector IDs. Retry a failed insert through the existing pending-document cleanup path. Restore the previous storage configuration and repeat from the saved source to roll back; do not rewrite stored provenance or re-use vectors generated for another model.

When a replacement is selected, implement it through `Embedder`, allocate a new vector-space version and a separate compatible index, and provide a staged migration before changing defaults. Persist the exact model, dimensions, metric and task mode at document/chunk creation. Keep old source exports, credentials and indexes available until verification and rollback are complete; rolling back code alone cannot restore deleted vectors. Apply no remote migrations or production changes as part of this evaluation.
